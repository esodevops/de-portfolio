Project overview

One repeatable route from raw sales to cloud-ready data.

Zipco Food's source file mixes customer, product, staff, store, payment, delivery, and transaction facts. This project packages the cleanup and normalization work into a clear three-stage Airflow workflow, producing reusable datasets for reporting and downstream analytics.

The challenge

A flat transaction file hides valuable structure.

Before the data can support dependable analysis, the workflow has to correct common quality problems and separate repeating business entities from transaction facts.

01

Duplicate records

Repeated rows inflate totals and weaken the reliability of sales reporting.

02

Missing values

Numeric gaps are filled with column means while missing text is labeled consistently.

03

Repeated entities

Customer, staff, and product details recur in the same wide transaction dataset.

04

Entity relationships

Generated IDs link each transaction to its product, customer, and staff records.

05

Manual processing

Airflow makes the extract, transform, and load sequence visible and repeatable.

06

Cloud delivery

Raw and processed assets are organized into separate Azure Blob Storage paths.

Data pipeline

Extract. Transform. Load.

The zipco_food_dag coordinates three Python tasks in sequence. Airflow provides retries and SMTP failure notifications, while each stage keeps a focused responsibility.

01

Extract

Read zipco_transaction.csv from the raw-data directory into a Pandas DataFrame.

02

Clean

Remove duplicate records and handle missing numeric and text values consistently.

03

Normalize

Create product, customer, and staff dimensions with generated IDs, then link them to transaction facts.

04

Export

Write the cleaned source plus four normalized CSV datasets to the local cleaned-data directory.

05

Publish

Upload the cleaned source to raw/ and the normalized datasets to processed/ in Azure Blob Storage.

06

Monitor

Retry failed tasks once and send an SMTP alert containing the DAG, task, run, and log details.

Data architecture

Small, purposeful analytical assets.

Normalization reduces repetition and gives downstream consumers focused files. Transactions retain the measurable business event while IDs connect each event to its descriptive entities.
